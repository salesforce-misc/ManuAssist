# Inventory Count — Overview

Inventory Count (also called Physical Inventory Count or **Cycle Count**) enables warehouse and service-parts teams to conduct periodic physical counts of inventory and reconcile discrepancies against system quantities. It is part of Manufacturing Cloud's broader Inventory Management capability.

A cycle count is initiated through the **`/connect/inventory/inventory-count` Connect REST API**, which asynchronously generates the assessment and line-level count records from a single call.

## Key Objects

The cycle count process spans **four** objects. Only the **Count Plan** is created directly; the other three are **system-generated** when the REST API is invoked.

| Object | API Name | Created By | Purpose |
|--------|----------|-----------|---------|
| Inventory Count Plan | `InventoryCountPlan` | Admin / API (direct create) | Parent — defines scope, location, schedule, and recurrence for a counting exercise |
| Inventory Count Plan Item | `InventoryCountPlanItem` | System (REST API) | Which product(s) are in scope for the plan; carries `IsBlindCount` |
| Inventory Count Assessment | `InventoryCountAssessment` | System (REST API) | The per-assignee counting task (`Status='Assigned'`, `Type='Periodic'`) |
| Inventory Count Product Item | `InventoryCountProductItem` | System (REST API) | Line-level count record, one per `ProductItem` in scope |

## Object Relationships

```
InventoryCountPlan  (scope + schedule + recurrence)
  ├── InventoryCountPlanItem        (product in scope; IsBlindCount)
  │     └── InventoryCountProductItem  (line per ProductItem; QuantityUnitOfMeasure, Status)
  └── InventoryCountAssessment      (AssigneeId → User or Queue; PlannedStartDateTime)
        └── InventoryCountProductItem  (linked via InventoryCountAssessmentId)
```

## InventoryCountPlan

Top-level record that groups all counting activities for a physical inventory event. **It has a native recurrence engine** — you do not need an external scheduler to run cycle counts on a cadence.

| Field | API Name | Type | Notes |
|-------|----------|------|-------|
| Name | `Name` | Text | Plan name |
| Status | `Status` | Picklist | e.g. `Active` |
| Location | `LocationId` | Lookup | Location/warehouse being counted (`Location.IsInventoryLocation = true`) |
| Start Date/Time | `StartDateTime` | DateTime | Planned start of the counting window |
| End Date/Time | `EndDateTime` | DateTime | Planned end of the counting window |
| Count Interval | `CountInterval` | Integer | How often the count recurs (e.g. `1`) |
| Count Interval Unit | `CountIntervalUnitOfMeasure` | Picklist | `Day` / `Week` / `Month` / `Quarter` — drives the cadence |
| Count Window Days | `CountWindowDays` | Integer | Number of days a counter has to complete each cycle |

> **ABC / frequency-tiered counting is native.** Count high-value SKUs daily/weekly and slow-movers quarterly by setting `CountInterval` + `CountIntervalUnitOfMeasure` per plan — no Flow scheduler required.

## InventoryCountAssessment

Represents an individual counting task assigned to a person or team. Generated by the REST API.

| Field | API Name | Type | Notes |
|-------|----------|------|-------|
| Inventory Count Plan | `InventoryCountPlanId` | Lookup | Parent plan |
| Assignee | `AssigneeId` | Polymorphic Lookup | Can reference **User** or **Queue** — labeled "Responsible Associate" |
| Location | `LocationId` | Lookup | Mirrors the plan's location |
| Status | `Status` | Picklist | `Assigned` on generation |
| Type | `Type` | Picklist | `Periodic` for recurrence-driven counts |
| Planned Start Date/Time | `PlannedStartDateTime` | DateTime | Derived from the plan's `StartDateTime` |

## InventoryCountProductItem

Line-level count record — one per `ProductItem` brought into scope by the API call.

| Field | API Name | Type | Notes |
|-------|----------|------|-------|
| Assessment | `InventoryCountAssessmentId` | Lookup | Parent assessment |
| Plan Item | `InventoryCountPlanItemId` | Lookup | Parent plan item |
| Product Item | `ProductItemId` | Lookup | The on-hand stock record being counted |
| Is Serialized Product | `IsSerializedProduct` | Boolean | Mirrors `Product2.IsSerialized` |
| Quantity Unit Of Measure | `QuantityUnitOfMeasure` | Text | e.g. `Each` |
| Status | `Status` | Picklist | `Assigned` on generation |

## Initiating a Count — Connect REST API

```
POST /services/data/v{API_VERSION}/connect/inventory/inventory-count
Authorization: Bearer {SESSION_ID}
Content-Type: application/json

{
  "productItemIds": ["<ProductItem Id>", "..."],
  "assignee": "<User or Queue Id>",
  "inventoryCountPlanId": "<InventoryCountPlan Id>",
  "isBlindCount": true
}
```

**Response:** `201 Created`, body `{ "isSuccess": true }`.

Behavior:
- **One call cascades.** A single POST generates an `InventoryCountPlanItem`, an `InventoryCountAssessment` (`Status='Assigned'`, `Type='Periodic'`), and one `InventoryCountProductItem` per `ProductItem` in `productItemIds`.
- **Generation is asynchronous.** The downstream records do not exist at the moment the `201` returns — poll (the E2E test waits up to ~33 min with a 5-min interval) until they appear.
- **`isBlindCount: true`** means the counter cannot see the system on-hand quantity, preserving count integrity. The flag propagates to `InventoryCountPlanItem.IsBlindCount`.
- **`assignee`** can be a **User** or a **Queue** Id (polymorphic `AssigneeId`).
- **Serialized + non-serialized** products can be counted in the same call; `InventoryCountProductItem.IsSerializedProduct` mirrors `Product2.IsSerialized`.

## Inventory Data Prerequisites

Cycle count operates over standard inventory master data:

| Object | Role |
|--------|------|
| `Location` | Warehouse / dealer / inventory location; `IsInventoryLocation = true`, `LocationType` ∈ `Warehouse` / `Dealer Location` / `Inventory Location` |
| `Product2` | The product; `IsSerialized` determines serialized vs. non-serialized counting |
| `ProductItem` | On-hand stock for a product at a location (`QuantityOnHand`, `QuantityUnitOfMeasure`) — the thing actually counted |
| `SerializedProduct` | Serial numbers for serialized `ProductItem`s (`SerialNumber`) |

## Known Platform Limitation: AssigneeId Field

`AssigneeId` on `InventoryCountAssessment` is a **polymorphic lookup** — it can point to either a `User` or a `Queue`. This causes two well-known UI limitations:

### 1. Cannot Add to Related List Columns (Page Layout)
When adding `InventoryCountAssessment` as a related list (on `InventoryCountPlan` or any other object such as `Account`), the page layout editor throws an error or silently omits `AssigneeId` when you try to include it as a display column. The layout editor cannot resolve a single target object type for polymorphic fields.

### 2. Not Visible in ARC (Schema Browser)
ARC (schema explorer tools) does not render polymorphic lookup fields the same way as standard lookups, making `AssigneeId` appear missing when browsing the `InventoryCountAssessment` object schema.

**Root cause:** Same class of issue as other polymorphic fields on the platform (`OwnerId`, `WhoId`, `WhatId`). The field exists in the data model and is fully queryable via SOQL — it is purely a UI rendering limitation.

## SOQL Quick Reference

```sql
-- All assessments for a count plan
SELECT Id, Name, AssigneeId, Status, Type, PlannedStartDateTime
FROM InventoryCountAssessment
WHERE InventoryCountPlanId = '<PlanId>'

-- Verify a generated assessment (matches the E2E assertion shape)
SELECT Id FROM InventoryCountAssessment
WHERE InventoryCountPlanId = '<PlanId>' AND AssigneeId = '<UserId>'
  AND LocationId = '<LocationId>' AND Status = 'Assigned' AND Type = 'Periodic'

-- Plan items (blind-count flag)
SELECT Id, InventoryCountPlanId, IsBlindCount, AssigneeId, ProductReferenceRecordId
FROM InventoryCountPlanItem
WHERE InventoryCountPlanId = '<PlanId>' AND IsBlindCount = true

-- Line-level product items for an assessment
SELECT Id, ProductItemId, IsSerializedProduct, QuantityUnitOfMeasure, Status
FROM InventoryCountProductItem
WHERE InventoryCountAssessmentId = '<AssessmentId>' AND Status = 'Assigned'

-- All count plans with assessment counts
SELECT Id, Name, Status, LocationId, CountInterval, CountIntervalUnitOfMeasure,
       (SELECT Id, Status FROM InventoryCountAssessments)
FROM InventoryCountPlan
```

> Note: `AssigneeId` is fully queryable via SOQL even though it does not render in the page layout editor or ARC.
